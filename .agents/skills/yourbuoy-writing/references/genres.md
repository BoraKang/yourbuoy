# 장르

세 갈래다. 각 장르는 사고 흐름(글의 뼈대)과 발행 형식(껍데기)으로
나뉜다. 뼈대가 먼저다. 형식을 다 갖춰도 사고 흐름이 없으면 그 장르
글이 아니다.

아래 표는 흔히 잘 맞는 출발점이다. 할당량이나 발행 조건이 아니다. 글의
원재료와 자연스러운 호흡이 다르면 그에 맞게 바꾼다.

| 장르 | 카테고리 | 분량 | 헤딩 | FAQ | 이미지 |
|---|---|---|---|---|---|
| 업무팁 | work, mind | 내용에 필요한 만큼 | 독자의 이해에 도움될 때 | 필요할 때만 | 설명에 도움될 때 |
| 일상 | life | 자연스러운 호흡만큼 | 보통 없음 | 보통 없음 | 필요할 때 |
| 개발기 | forge, ai | 과정을 보여줄 만큼 | 흐름 구분이 필요할 때 | 필요할 때만 | 과정 이해에 도움될 때 |

---

## 업무팁 (work / mind)

실제 업무에서 겪으며 알아낸 요령을 다른 사람이 가져다 쓸 수 있게 한다.

### 사고 흐름

```
이런 문제가 있었다
→ 처음에는 이렇게 했다
→ 그런데 잘 안 됐다
→ 나중에 보니 이유가 이것이었다
→ 그래서 이렇게 바꿨다
→ 실제로는 이렇게 사용한다
→ 다만 이런 상황에서는 다를 수 있다
```

마지막 줄이 발행 원칙 3(정답처럼 말하지 않는다)의 실행이다. 필요하면
끝에 체크리스트·템플릿을 붙인다.

### 원재료 체크

실제 문제 / 당시 상황 / 처음 했던 생각 / 기존 방법이 안 됐던 이유 /
시행착오 / 지금 쓰는 방법 / 실제 사례. 이 중 시행착오와 실제 사례가
없으면 Idea Rescue에서 묻는다.

### 발행 형식

- 독자의 반론이 실제로 중요한 글이면 도입이나 적절한 위치에서 다룬다
- 절차를 설명할 때만 번호 목록이나 단계형 H3를 쓴다
- 실명 툴·책·양식·캡처는 글의 근거 또는 이해에 도움이 될 때 쓴다
- 마무리는 글에서 생긴 생각으로 끝낸다. FAQ는 별도 질문을 다루는 편이
  본문보다 명확할 때만 붙인다

## 일상 (life)

일어난 일과 그때의 생각을 기록한다. 독자를 가르치는 것이 목적이
아니다. 다른 장르와 반대로, 덜 완성하려는 노력이 필요하다.

### 사고 흐름

```
어떤 장면
→ 그때 든 생각
→ 다른 기억이나 경험
→ 생각이 조금 달라짐
→ 지금 드는 생각
```

여기서 끝나도 된다. 결론이 없어도 발행한다.

### 금지

- 억지 교훈, 삶의 지혜 N가지, 독자 훈계
- 감정을 과장해서 문학적으로 포장
- 모든 경험에 의미 부여
- 분량 늘리기, H2 붙이기, FAQ 붙이기

### 발행 형식

대체로 헤딩 없이 문단으로 흐르게 쓰지만, 긴 회고에서 시간이나 장면을
구분해야 한다면 헤딩을 쓸 수 있다. 문단 수와 분량은 강제하지 않는다.
이미지와 내부 링크도 글에 도움이 될 때만 쓴다.

## 개발기 (forge / ai)

완성된 튜토리얼이 아니라 실제로 만들면서 어떻게 헤맸는지를 남긴다.
오류와 삽질을 제거하지 않는다. 처음 생각 → 실패 → 변경 → 결과가
핵심 콘텐츠다. 미완성 프로젝트도 발행할 수 있다.

### 사고 흐름

```
뭘 만들려고 했나
→ 왜 만들려고 했나
→ 처음 생각한 구조
→ 실제로 해봄
→ 막힘
→ 찾아봄 / 바꿈
→ 다시 시도
→ 현재 상태
→ 다시 한다면 어떻게 할지
```

"막힘"이 비어 있으면 발행하지 않는다. 홍보문이 된다. "만들려다 못
만든 이유를 알게 됐다"도 막힘에 해당한다.

### 발행 형식

- 날짜·수량·소요시간처럼 과정 이해에 중요한 숫자가 있으면 정확히 쓴다
- 전후 비교가 실제 변화의 핵심이고 근거가 있을 때만 숫자로 대비한다
- 결과물 링크나 캡처는 독자의 이해나 검증에 도움이 될 때 넣는다. 내부
  전용이라 독자가 못 쓰면 그 사실을 명시한다
- FAQ는 본문에 넣으면 흐름을 끊지만 따로 답할 가치가 있는 질문이 있을
  때만 붙인다

### 사실 검증 (F-1)

기술적 원인은 본인이 실제로 이해한 범위까지만 쓴다. AI가 그럴듯한
메커니즘을 채우지 않는다.

- 좋음: "구글이 익스텐션 쪽에서 문서 실제 변경을 막고 있었다"
- 나쁨: "DOM 조작 방식이라 저장된 속성은 그대로 남는다"
  (확인 안 된 설명을 AI가 지어낸 실제 사례. 2026-08)

원인을 모르면 원인을 쓰지 않는다. "안 된다는 걸 알게 됐다"까지만
써도 글은 성립한다.
