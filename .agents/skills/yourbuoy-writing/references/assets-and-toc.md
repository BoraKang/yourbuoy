# 이미지와 TOC 규칙

본문 이미지, 반응형 이미지 배열, 미사용 파일 정리 또는 TOC를 다룰 때 읽는다.

## 이미지 저장

- 히어로·썸네일: `assets/images/thumbnail/`
- 본문 이미지: `assets/images/posting/YYMMDD/`
- `_posts/`, 저장소 루트, `/var/folders`, `/tmp`에는 최종 이미지를 두지 않는다.
- `orca-paste-*`나 난수 파일명은 의미 있는 영문 kebab-case로 바꾼다.
- 이미지 내용, `hero_image`, 본문 참조 위치를 함께 보고 썸네일과 본문
  이미지를 구분한다.
- 동일 이미지를 여러 이름으로 중복 저장하지 않는다.
- 정보성 이미지에는 구체적인 대체 텍스트를 넣는다.

사진 묶음을 받으면 먼저 개수와 중복을 확인한다. 수평이 1도 이상
틀어진 사진은 보정하고, 손가락·다른 사람의 얼굴·과도한 빈 공간은
필요할 때 자른다. JPEG는 품질 85, 가로 1200px 안팎을 기본으로 하되
원본보다 키우지 않는다. `orca-paste-*` 원본은 의미 있는 파일명으로
바꾼 최종본만 커밋한다.

예:

```text
orca-paste-1791016391683-….png
→ assets/images/posting/260922/phu-quoc-island-aerial.png
```

```markdown
![푸꾸옥의 에메랄드빛 바다와 해양 액티비티](/assets/images/posting/260922/phu-quoc-island-aerial.png)
```

## 이미지 배열

- 데스크톱의 2열·3열 배열은 모바일에서 1열로 바꾼다.
- 이미지의 원래 비율을 왜곡하지 않는다.
- 같은 행의 폭, 높이, 하단선을 시각적으로 맞춘다.
- `object-fit: cover`를 쓰면 중요한 내용이 잘리지 않는지 확인한다.
- 같은 정보를 반복하는 장식 이미지는 줄이고 지도·절차·가격처럼 이해에
  필요한 이미지를 우선한다.

이미지 2장을 한 행에 배치할 때는 Markdown 이미지를 연달아 두는 데 기대지
말고 전용 그리드를 쓴다. 기본 구현은 다음과 같다.

```css
.image-pair {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 12px;
}
.image-pair img {
  width: 100%;
  aspect-ratio: 1 / 1;
  object-fit: cover;
}
@media (max-width: 640px) {
  .image-pair { grid-template-columns: 1fr; }
  .image-pair img { aspect-ratio: auto; height: auto; }
}
```

- 두 이미지가 가로형이면 정사각형을 강제하지 말고 공통 고정 높이를 쓸 수
  있다. 어느 쪽이든 같은 행에서는 같은 높이로 보이게 한다.
- 자막·텍스트·핵심 피사체가 잘리는 이미지에는 `cover` 대신 `contain`과
  중립 배경을 쓴다.
- 사용자가 명시적으로 세로 배열을 요청하지 않은 이미지 2장은 데스크톱
  2열을 기본값으로 본다.

## 미사용 이미지 정리

1. 대상 글의 이미지 참조를 수집한다.
2. 저장소 전체에서 각 후보 파일명의 참조 여부를 검색한다.
3. 다른 글이 사용하는 파일은 보존한다.
4. 사용되지 않는 이전 버전, 임시 붙여넣기 이미지, 빈 임시 문서를 후보로
   분류한다.
5. 사용자가 정리를 요청했을 때만 이동하거나 삭제한다.
6. 가능하면 휴지통으로 옮겨 복구 가능하게 하고 결과를 알린다.

파일명만 보고 삭제하지 않는다.

## TOC 구조

- H1은 front matter의 `title` 하나만 둔다.
- H2는 큰 흐름, H3는 H2 아래 세부 질문과 사례에 사용한다.
- 목차를 채우려고 필요 없는 헤딩을 만들지 않는다.
- `data-toc` 표시명은 공백과 문장부호를 포함해 **한글 기준 15자
  이내**를 기본값으로 한다. 이 길이는 `_sass/custom.scss`의
  `.page__aside .toc` 사이드바 폭을 기준으로 한 실측치다. 한눈에 읽히는
  명사구로 줄이고, 제목 문장을 그대로 반복하지 않는다.
- 15자를 넘으면 의미를 보존하는 선에서 먼저 줄이되, 사용자가 직접 정한
  표시명은 길이보다 우선한다. 넘어간 표시명은 2줄로 바뀐 수 있고
  `-webkit-line-clamp: 2`는 보조 안전장치로만 본다.

TOC에 짧은 표시명을 쓰려면 속성을 제목 바로 다음 줄에 둔다.

```markdown
## 푸꾸옥 숙소, 어디로 예약할까?
{: data-toc="리조트 고르기"}

본문이 시작된다.
```

제목과 `data-toc` 사이에 빈 줄을 넣지 않는다. 빈 줄이 있으면 속성이 다음
문단이나 목록에 붙는다.

## TOC 검증

렌더링된 HTML에서 다음을 확인한다.

- `data-toc`가 `<h2>` 또는 `<h3>`에 붙었는가
- `<p>`, `<ul>`, `<ol>`, `<div>`에 잘못 붙은 속성이 없는가
- 링크가 해당 헤딩의 `id`로 이동하는가
- 지정한 짧은 이름이 데스크톱 TOC에 표시되는가

현재 TeXt 테마 설정은 모바일·태블릿에서 사이드 TOC를 숨긴다. 모바일에서
TOC가 보이지 않는 현상을 오류로 단정하지 말고 테마 동작임을 먼저 알린다.
