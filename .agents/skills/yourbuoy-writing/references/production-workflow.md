# 글 제작·발행 워크플로

실제 Markdown 파일을 편집하거나 배포할 때 읽는다. 목소리와 문장 규칙은
`voice.md`가 담당하며, 이 문서는 사용자의 최신 저장본과 제작 범위를 지키는
절차만 다룬다.

## 시작할 때 한 번에 제안

이미지가 많거나 H2·H3가 많은 장문은 본문을 고치기 전에 다음을 한 번에
제안한다.

1. 글이 하려는 말 한 문장
2. 권장 H2·H3 구조
3. 사이드 TOC에 표시할 짧은 이름
4. 이미지별 위치와 데스크톱·모바일 배열
5. 확인할 사실이나 빈 부분

간단한 글, 구조가 이미 확정된 글, 사용자가 바로 편집을 지시한 글에는 이
단계를 강제하지 않는다.

| 본문 구조 | TOC 표시명 | 이미지 계획 |
| --- | --- | --- |
| 우기에 가도 괜찮을까? | 여행 시기 | 날씨 예보 1장 |
| 어떤 시간대가 좋을까? | 항공편 | 항공사 이미지 2열 |
| 환율과 환전 얼마나? | 환율과 환전 | 화폐 이미지 2열 |

## 최신 저장본 보호

Orca 등에서 사용자가 직접 수정 중이면 사용자의 최신 저장본이 정본이다.

1. 작업 직전에 대상 파일을 다시 읽는다.
2. 변경 전 상태나 diff를 확인한다.
3. 요청받은 범위만 수정한다.
4. 커밋 직전에 파일을 다시 읽어 예상하지 않은 저장이 생겼는지 확인한다.
5. 사용자의 새 저장이 있으면 이전 본문을 되살리지 않는다.
6. 최신 저장본 위에 요청받은 구조·이미지·TOC 변경만 다시 적용한다.
7. 배포 직후에도 늦은 자동 저장이 생겼는지 확인한다.

어느 버전이 최신인지 판단할 수 없으면 임의로 병합하지 말고 차이를 알린다.

## 모드별 변경 범위

### 편집 모드

- 문장 수정·교정·재구성을 요청받은 범위에서 수행한다.
- 사용자의 경험, 의미, 말투를 임의로 바꾸지 않는다.
- 범위가 모호하면 기존 문장을 보존한다.

### 제작 모드

- 이미지, 레이아웃, 링크, 박스, 헤딩 수준, TOC만 변경한다.
- 본문 문장은 수정하지 않는다.
- 이미지 대체 텍스트와 TOC 속성처럼 렌더링에 필요한 메타 정보는 고칠 수
  있다.

### 발행 모드

- 저장된 최신 버전을 그대로 발행한다.
- 오탈자를 발견해도 자동 수정하지 않고 별도로 알린다.
- 관련 없는 파일을 스테이징하거나 배포하지 않는다.

## 배포 전 검사

- 최신 사용자 저장본인지 확인한다.
- 요청하지 않은 본문 변경이 없는지 diff로 확인한다.
- front matter와 `hero_image` 경로를 확인한다.
- 본문이 참조하는 이미지가 모두 존재하는지 확인한다.
- 임시 이미지 경로와 파일명이 남지 않았는지 확인한다.
- 데스크톱 이미지 배열과 모바일 1열 전환을 확인한다.
- `data-toc`가 헤딩에 붙었는지 확인한다.
- 가능한 로컬 빌드를 실행한다. 로컬 환경 문제로 실패하면 원인과 범위를
  밝히고 CI 빌드로 검증한다.

## 배포 후 검사

- GitHub Pages 빌드와 배포 성공 여부
- 실제 포스트 URL의 HTTP 200 응답
- 새 이미지 URL의 HTTP 200 응답과 픽셀 크기
- 렌더링된 HTML의 TOC 속성 위치
- 삭제한 공개 파일이나 이전 임시 경로의 잔존 여부
- 배포 직후 사용자의 늦은 자동 저장 여부

## 완료 보고

결과만 간결하게 알린다.

- 반영한 구조·이미지·TOC 변경
- 본문 수정 여부
- 정리한 파일 수와 복구 가능 여부
- 빌드·배포 결과와 실제 글 링크
- 발견했지만 수정하지 않은 오탈자나 주의점
