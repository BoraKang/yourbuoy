# 장르

세 갈래다. 각 장르는 사고 흐름(글의 뼈대)과 발행 형식(껍데기)으로
나뉜다. 뼈대가 먼저다. 형식을 다 갖춰도 사고 흐름이 없으면 그 장르
글이 아니다.

| 장르 | 카테고리 | 분량 | 헤딩 | FAQ | 이미지 |
|---|---|---|---|---|---|
| 업무팁 | work, mind | 3,000~6,000자 | H2 3~5 + 번호 H3 | 3문항 | 4~5장 |
| 일상 | life | 700~1,200자 | 없음 | 없음 | 히어로만 |
| 개발기 | forge, ai | 2,500~4,000자 | H2 3~5 | 3문항 | 2~4장 |

---

## 업무팁 (work / mind)

실제 업무에서 겪으며 알아낸 요령을 다른 사람이 가져다 쓸 수 있게 한다.

### 사고 흐름

```
이런 문제가 있었다
→ 처음에는 이렇게 했다
→ 그런데 잘 안 됐다
→ 나중에 보니 이유가 이것이었다
→ 그래서 이렇게 바꿨다
→ 실제로는 이렇게 사용한다
→ 다만 이런 상황에서는 다를 수 있다
```

마지막 줄이 발행 원칙 3(정답처럼 말하지 않는다)의 실행이다. 필요하면
끝에 체크리스트·템플릿을 붙인다.

### 원재료 체크

실제 문제 / 당시 상황 / 처음 했던 생각 / 기존 방법이 안 됐던 이유 /
시행착오 / 지금 쓰는 방법 / 실제 사례. 이 중 시행착오와 실제 사례가
없으면 Idea Rescue에서 묻는다.

### 발행 형식

- 도입은 독자의 반론 인용으로 (voice.md V-5)
- `## ~하면 좋은 점` 번호 목록 → `## ~의 기술` 아래 번호 H3
- 실명 툴·책 링크, 본인 양식·캡처 최소 1장
- 마무리는 자기 조언을 깎는 문장 (V-6), FAQ 3문항

## 일상 (life)

일어난 일과 그때의 생각을 기록한다. 독자를 가르치는 것이 목적이
아니다. 다른 장르와 반대로, 덜 완성하려는 노력이 필요하다.

### 사고 흐름

```
어떤 장면
→ 그때 든 생각
→ 다른 기억이나 경험
→ 생각이 조금 달라짐
→ 지금 드는 생각
```

여기서 끝나도 된다. 결론이 없어도 발행한다.

### 금지

- 억지 교훈, 삶의 지혜 N가지, 독자 훈계
- 감정을 과장해서 문학적으로 포장
- 모든 경험에 의미 부여
- 분량 늘리기, H2 붙이기, FAQ 붙이기

### 발행 형식

헤딩 없이 문단 4~6개. 히어로 이미지 한 장. 내부 링크 강제 없음.

## 개발기 (forge / ai)

완성된 튜토리얼이 아니라 실제로 만들면서 어떻게 헤맸는지를 남긴다.
오류와 삽질을 제거하지 않는다. 처음 생각 → 실패 → 변경 → 결과가
핵심 콘텐츠다. 미완성 프로젝트도 발행할 수 있다.

### 사고 흐름

```
뭘 만들려고 했나
→ 왜 만들려고 했나
→ 처음 생각한 구조
→ 실제로 해봄
→ 막힘
→ 찾아봄 / 바꿈
→ 다시 시도
→ 현재 상태
→ 다시 한다면 어떻게 할지
```

"막힘"이 비어 있으면 발행하지 않는다. 홍보문이 된다. "만들려다 못
만든 이유를 알게 됐다"도 막힘에 해당한다.

### 발행 형식

- 도입에 숫자를 넣는다 (날짜, 수량, 소요시간)
- 전후 숫자 대비 1쌍 (예: 20분 → 10초)
- 결과물 링크나 캡처. 내부 전용이라 독자가 못 쓰면 그 사실을 명시
- FAQ 3문항

### 사실 검증 (F-1)

기술적 원인은 본인이 실제로 이해한 범위까지만 쓴다. AI가 그럴듯한
메커니즘을 채우지 않는다.

- 좋음: "구글이 익스텐션 쪽에서 문서 실제 변경을 막고 있었다"
- 나쁨: "DOM 조작 방식이라 저장된 속성은 그대로 남는다"
  (확인 안 된 설명을 AI가 지어낸 실제 사례. 2026-08)

원인을 모르면 원인을 쓰지 않는다. "안 된다는 걸 알게 됐다"까지만
써도 글은 성립한다.
