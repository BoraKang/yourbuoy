# 학습 루프

발행은 끝이 아니라 관측의 시작이다. 이 문서는 결과를 스킬 규칙으로
바꾸는 절차다.

성공 기준은 두 층이다.

- **시스템 지표**: 묵혀 있던 아이디어가 발행 가능한 글로 몇 편
  살아났는가. 이 시스템의 북극성이다. 분기마다 센다.
- **글 지표**: 장르별 지표(L-2). 글 단위 가설 검증에 쓴다.

AI가 좋은 글을 처음부터 만들어냈는가는 성공 기준이 아니다.

앞선 `evals/harness.md`와 역할이 다르다. 하네스는 스킬이 규칙대로
도는지를 본다. 이 문서는 그 규칙이 맞았는지를 본다.

---

## L-0. 원칙: 한 편으로 규칙을 바꾸지 않는다

글 하나 잘됐다고 규칙을 고치면 다음 글에서 또 흔들린다. 반대도 같다.
안 됐다고 지우거나 방향을 틀지 않는다.

규칙 변경은 **같은 방향 결과가 3편 이상** 쌓이고 **최소 노출 기준**을
넘겼을 때만 한다(L-4). 그 전까지 모든 관측은 관측으로만 남긴다.

---

## L-1. 발행 시 가설을 적는다

글을 커밋하기 전에 원장에 한 줄을 추가한다. 예측 없이 측정하면 결과를
사후 해석하게 된다.

원장 위치: `_meta/ledger.md`

| 필드 | 내용 |
|---|---|
| slug | 글 주소 |
| 발행일 | YYYY-MM-DD |
| 장르 | 업무팁 / 일상 / 개발기 |
| 노린 검색어 | internal_tags 중 1순위 하나 |
| 가설 | 이 글이 왜 먹힐 거라 보는지 한 문장 |
| 실험 요소 | 이번에 처음 시도한 것 하나 (없으면 "없음") |
| 예측 | D+90에 기대하는 값. 숫자로 |

실험 요소는 한 편에 하나만 넣는다. 두 개를 동시에 바꾸면 뭐가 먹혔는지
모른다.

---

## L-2. 무엇을 재는가 (장르별로 다르다)

| 장르 | 1차 지표 | 2차 지표 | 무시할 것 |
|---|---|---|---|
| 업무팁 | 검색 노출수, 클릭수, 평균 게재순위 | 체류시간 | 발행 첫 주 유입 |
| 일상 | 구독 전환, 재방문 | 댓글 | 검색 노출 |
| 개발기 | AI 경유 방문, 구독 전환 | 검색 노출 | 소셜 반응 |

발행 직후 유입은 지인과 소셜에서 온다. 글의 품질이 아니라 공유 여부를
잰다. 업무팁의 첫 주 숫자는 보지 않는다.

일상 글을 검색 지표로 평가하지 않는다. 애초에 검색용이 아니다.

---

## L-3. 언제 재는가

- **D+30 1차** — 색인 됐는지, 어떤 검색어로 걸리는지 확인. 판정하지 않는다.
- **D+90 확정** — 예측과 대조하고 원장에 결과를 적는다.
- **분기 리뷰** — 확정된 글이 3편 이상 모이면 L-4를 실행한다.

업무팁은 색인과 순위 안정에 시간이 걸린다. 90일 전에 결론 내지 않는다.

### 데이터 가져오는 곳

- Search Console: 쿼리별 노출·클릭·CTR·평균순위. 수동 내보내기(CSV)
- Ahrefs MCP: yourbuoy.kr 유입 키워드와 순위 변화
- GA4/GTM(GTM-W8NMB79): 유입 경로, 구독 전환
- AI 경유 방문: referrer가 chatgpt.com, perplexity.ai, gemini.google.com 등

GA4가 연동되기 전에는 Search Console과 Ahrefs만으로 돌린다. 그때는
업무팁만 평가하고 일상·개발기는 관측만 쌓는다.

---

## L-4. 결과를 규칙으로 승격하는 절차

### 승격 요건 (전부 충족해야 함)

1. 같은 방향의 결과가 **글 3편 이상**에서 나왔다
2. 그 글들의 합산 노출이 **1,000회 이상**이다 (업무팁 기준)
3. 다른 설명이 더 그럴듯하지 않다 (계절성, 외부 링크, 검색어 자체의 변동)
4. 규칙으로 적을 수 있을 만큼 구체적이다

### 승격되지 않는 것

- 글 1~2편의 결과
- 노출이 세 자리 이하인 구간의 CTR 차이
- "느낌상 이게 더 잘 읽히는 것 같다"
- 남의 블로그에서 봤다

이런 건 `_meta/ledger.md` 하단 관측 메모에만 적는다. 3편이 쌓이면
그때 다시 본다.

### 규칙을 적는 방식

승격된 규칙은 해당 파일에 근거 주석을 달아서 넣는다.

```markdown
## W-7. 업무팁 제목에 숫자를 넣는다

근거: 2026-09~2026-12 업무팁 5편 중 제목에 수치가 있는 3편의
평균 게재순위가 8.2위, 없는 2편이 19.4위. 합산 노출 3,400회.
확정일 2027-01-05.
```

근거 없는 규칙은 넣지 않는다. 나중에 그 규칙이 왜 있는지 몰라서
못 지우게 된다.

### 규칙을 빼는 절차

승격된 규칙도 이후 3편에서 반대 결과가 나오면 내린다. 넣을 때와 같은
요건을 적용한다. 규칙 수가 계속 늘기만 하는 스킬은 지켜지지 않는다.

---

## L-5. 분기 리뷰 진행 순서

1. 원장에서 D+90이 지난 글을 모은다
2. 글마다 예측 대비 결과를 적중 / 빗나감 / 판단보류로 표시한다
3. 빗나간 것부터 본다. 적중은 배울 게 적다
4. 3편 이상 같은 방향이면 L-4 승격 요건을 검토한다
5. 규칙을 고쳤으면 `evals/harness.md`를 돌려서 스킬이 여전히 도는지 본다
6. 리뷰 결과를 원장 하단에 날짜와 함께 남긴다

5번을 건너뛰지 않는다. 규칙을 추가하다가 기존 규칙과 충돌하면
하네스에서 잡힌다.

---

## L-6. 원장 양식

```markdown
# yourBuoy 원장

## 발행 기록

| slug | 발행일 | 장르 | 노린 검색어 | 가설 | 실험 요소 | 예측 | D+30 | D+90 | 판정 |
|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | |

## 관측 메모 (승격 전)

- YYYY-MM-DD / 관측 내용 / 관련 글 수

## 분기 리뷰

### YYYY-QN
- 구조된 아이디어: 발행 N편 / 초안 보류 N편 / 사망 N편
- 검토한 글:
- 승격한 규칙:
- 내린 규칙:
- 하네스 재실행 결과:
```
