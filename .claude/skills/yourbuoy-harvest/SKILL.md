# yourBuoy Harvest

목표는 글을 대신 쓰는 것이 아니라 이미 남은 흔적과 확인 가능한 외부 수요를
발견해 사용자가 고를 수 있는 후보로 만드는 것이다. 이 스킬은 후보 제안에서
멈춘다. 사용자 승인 전에는 Notion을 수정하거나 초안을 쓰지 않는다.

## 실행 모드

단일 에이전트가 조사, 중복 제거, 후보화를 순서대로 수행한다. 멀티에이전트는
사용하지 않는다.

- **수요 우선:** 정기 자동화의 기본값. 검색 질문에서 출발해 독자 수요와
  경쟁 글의 빈틈을 찾은 뒤 사용자의 경험과 연결한다.
- **흔적 우선:** 사용자가 메모·대화·프로젝트를 지정했을 때 사용한다. 내부
  흔적에서 출발해 공개 수요를 확인한다.

## 수요 우선 주제

### AX 리더십

AI 도구 소개보다 리더와 팀이 AI를 실제 업무에 도입하는 과정에 집중한다.

- 도입 판단, 우선순위, 기대치와 성과 정의
- 팀의 사용 습관, 역할 변화, 교육, 저항과 변화관리
- 책임, 검수, 품질, 보안, 거버넌스
- 리더가 직접 겪은 시행착오와 운영 원칙

### 업무 운영(Work Operations)

개인의 생산성 팁보다 일이 팀 안에서 반복 가능하게 흐르는 방식을 다룬다.

- 프로세스 설계, 인수인계, 승인, 문서화, 회고
- 자동화·에이전트·n8n을 실제 운영에 붙이는 법
- 업무 측정, 실패 감지, 예외 처리, 유지보수
- 협업 도구와 데이터가 끊기는 지점

마케팅은 독립 기둥으로 조사하지 않는다. Martech, 콘텐츠 운영, 실험 측정처럼
AX 리더십 또는 업무 운영의 사례가 되는 경우에만 포함한다.

## 입력 우선순위

1. 사용자가 이번 실행에 준 대화·메모·링크
2. 최근 14일 프로젝트의 `README.md`, `status.md`, `work.md`, 결정·회고 문서
3. 사용자가 블로그 재료로 지정한 Obsidian 메모
4. 공개 검색 결과
5. GSC·Ahrefs는 실제 커넥터와 권한이 확인된 경우에만 사용

개인 일기나 Daily Catch 전체를 임의로 훑지 않는다. Daily Catch에서 씨앗을
뽑는 일은 별도의 주간 씨앗 선별 루프가 담당한다. 비밀 파일, 고객 데이터,
`.env`, 대화 전문은 읽거나 결과에 복제하지 않는다.

## 흐름

### 0. 실행 범위 확인

- 사용자가 일부 소스나 주제를 지정하면 그 범위만 다시 실행한다.
- 정기 자동화 또는 지정이 없으면 `수요 우선`으로 실행한다.
- 사용자가 자료를 지정하면 `흔적 우선`으로 실행한다.
- 읽을 수 없는 소스는 한 번 재시도한 뒤 누락 사실을 보고하고 계속한다.

### 1. 기존 Backlog 확인

Notion의 yourBuoy Blog Backlog를 읽어 제목, 핵심 주장, 출처, 상태를 파악한다.
접근할 수 없으면 중복 검사가 제한되었다고 밝히고 후보를 `임시`로 표시한다.

### 2. 내부 흔적 수확

다음 신호가 있는 흔적만 후보화한다.

- 실제로 해본 일, 막힌 지점, 되돌린 결정, 반복해서 설명한 문제
- 전후 차이, 예상과 달랐던 결과, 재사용 가능한 업무 요령
- 미완성이더라도 구체적인 장면이나 산출물이 남은 일

단순 TODO, 남의 주장 요약, 맥락 없는 한 문장은 제외한다.

### 3. 공개 수요 조사

수요 우선에서는 AX 리더십과 업무 운영의 구체적인 질문형·문제형 검색어부터
찾는다. 검색 결과, 관련 질문, 공식 문서, 실무 커뮤니티에서 반복되는 표현을
교차 확인하고 상위 원문을 연다. 다음을 기록한다.

- 독자: 어떤 역할의 사람이 어떤 상황에서 찾는가
- 검색 의도: 개념 이해, 비교, 실행법, 문제 해결 중 무엇인가
- 수요 근거: 서로 독립적인 공개 출처에서 질문이 반복되는가
- 경쟁 빈틈: 상위 글이 일반론·도구 나열에 머물거나 실제 운영 경험이 빠졌는가
- 경험 연결: 사용자의 프로젝트 흔적이나 답할 수 있는 경험이 있는가

흔적 우선에서는 내부 흔적에서 검색어를 만든 뒤 같은 항목을 확인한다. 제목과
스니펫만으로 단정하지 않는다. 검색량이나 순위는 실제 데이터가 없으면
추정하지 않는다. 외부 수요만 있고 사용자 경험이 없는 항목은 `조사 후보`다.

### 4. 중복 제거와 점수화

수요 우선 후보는 아래 4개 기준으로 0~2점 평가한다.

- 수요 근거: 독립된 공개 출처에서 같은 문제가 반복되는가
- 독자 적합성: AX 리더 또는 업무 운영 담당자의 검색 의도가 분명한가
- 경쟁 빈틈: 기존 글과 다른 실제 운영 관점을 더할 여지가 있는가
- 경험 연결성: 사용자가 답할 경험이나 프로젝트 흔적이 있는가

흔적 우선 후보는 아래 기준으로 평가한다.

- 경험성: 사용자의 구체적 흔적이 있는가
- 독자성: 누가 어떤 상황에서 읽을지 분명한가
- 차별성: 기존 Backlog·발행 글과 다른가
- 시의성: 지금 다룰 이유나 확인 가능한 수요가 있는가

두 모드 모두 6점 미만은 보고하지 않는다. 비슷한 후보는 합친다. 정기 수요
우선 실행은 최대 3개, 사용자가 직접 요청한 수확은 최대 5개만 남긴다.

### 5. 제안

후보마다 다음 형식을 사용한다.

```
1. 후보 제목
- 유형: 내 흔적에서 수확 | 검색 수요에서 수확 | 조사 후보
- 대상 독자·검색 의도: 역할 / 상황 / 의도
- 원재료: 파일 경로·메모명 또는 공개 링크
- 수요 근거·경쟁 빈틈: 확인한 신호를 짧게
- 핵심: 이 글에서 할 수 있는 말 한 문장
- 지금인 이유: 구체적 신호
- 빠진 경험: 없으면 "없음", 있으면 사용자에게 물을 질문 1개
- 추천 장르: work | mind | life | forge | ai
- 점수: 사용한 모드의 네 기준 = 합계
```

마지막에 `Backlog에 넣을 번호를 골라줘`라고 묻는다. 선택을 받으면 제목,
핵심, 출처, 추천 장르, 원재료 링크만 Notion에 등록한다. 경험 연결이 확인된
후보만 `씨앗`으로 두고, 경험이 확인되지 않은 `조사 후보`는 질문에 답하기
전까지 등록하지 않는다. 사용자가 선택하지 않으면 아무것도 저장하지 않는다.

## 금지

- 사용자 경험을 만들어내거나 외부 사례를 사용자 경험처럼 쓰기
- 검색량·순위·GSC·Ahrefs 데이터를 연결 없이 보유한 것처럼 말하기
- 후보를 초안, 교훈, 해결책으로 부풀리기
- 승인 없이 Notion 생성·수정, 발행, 커밋, 푸시하기
- Daily Catch를 글감이 되도록 유도하거나 회고 루프와 합치기

## 테스트 시나리오

- 정상: 최근 프로젝트 문서와 공개 검색을 조사해 중복 없는 후보 1~5개를
  제안하고 Notion은 수정하지 않는다.
- 수요 우선: AX 리더십·업무 운영에서 독자 질문과 경쟁 빈틈이 있는 후보를
  최대 3개 제안하고, 마케팅 일반 주제는 제외한다.
- 중복: 내부 흔적이 기존 Backlog와 같으면 새 후보 대신 기존 항목과의 연결을
  보고한다.
- 오류: Notion 또는 검색 접근이 실패하면 한 번 재시도하고, 제한을 명시한 뒤
  접근 가능한 내부 흔적만 `임시` 후보로 제안한다.
